Build better projects with smarter questions

In this workbook, every topic includes an Ask A.I. box. Use it when you are stuck on animation, custom blocks, storytelling flow, or broadcasting logic.

How A.I. helps in Level 2

A.I. can help you debug faster, suggest cleaner block order, improve script structure, and explain why your project behaves in a certain way. It is most useful when your projects become bigger and multiple sprites, sounds, and messages work together.

3 Golden Rules for Level 2 A.I. Prompts

1

Share your goal

Example: "I want my sprite to enter, speak, and trigger scene 2 with a broadcast."

2

Share your current blocks

Tell A.I. which blocks you used and in what order. This helps it find the real issue.

3

Ask for step-by-step fix

Ask for 3-5 steps so you can test one change at a time and learn while debugging.

Prompt example for this level
I am making a Scratch story with 3 sprites. Sprite A broadcasts scene2_start, but Sprite C is not reacting. I already added when I receive scene2_start in Sprite C. Can you give me a checklist to debug message spelling, receiver scripts, and timing conflicts with forever loops?

This works well because it includes your goal, current setup, and specific error.

Golden Rule - Try by yourself first, then ask A.I. as a coach. The best coders do not copy answers; they test, observe, improve, and understand.

1.1 Sprites and Animation

Chapter 1Sprites and Animation
â˜…

Big Idea

Animation is just a smart sequence of tiny changes: move a little, switch costume, wait a little, repeat.

Explanation In Scratch, animation is not one magical block. It is created by combining motion + looks + timing. If you change position without changing costume, movement may look stiff. If you change costume without timing, it can look like flicker. Good animation balances all three.

Core animation pattern

1

Start with an event

Use when green flag clicked or when key pressed so animation starts at the right time.

2

Switch costumes

Alternating costumes creates the illusion of walking or flapping.

3

Add wait for smoothness

Even a short wait like 0.1 seconds makes motion readable and natural.

4

Loop it

Use repeat for a fixed dance and forever for continuous animation.

Motion Blocks

Use move, glide, and turn for travel and direction.

Looks Blocks

Use next costume and change size for visual expression.

Control Blocks

Use repeat and wait to set rhythm and speed.

Example script

Walking animation (basic)

when green flag clicked
repeat 16
  next costume
  move 6 steps
  wait 0.12 seconds

What to observe

  • Lower wait = faster animation
  • Lower move + more repeats = smoother travel
  • Add if on edge, bounce for screen-safe motion
Try It! - 8 minutes

Walking Cat Test

  1. Add two cat costumes with different leg positions.
  2. Create a script: flag clicked -> repeat 20 -> next costume -> move 8 steps -> wait 0.1.
  3. Change wait from 0.1 to 0.3 and compare both versions.
Debug Tip If animation looks jumpy, reduce move distance and reduce wait time together.
Ask A.I.

Stuck? Try this prompt -

I am building a Scratch animation with one sprite. I want it to walk smoothly from left to right using next costume, move, and wait. Right now it looks jumpy. Can you suggest a good block order and starter values for move and wait, and explain how to adjust speed without breaking smoothness?

Tip: Mention what looks wrong (too fast, too slow, too jumpy) so A.I. gives better tuning advice.

2.1 Understanding Custom Blocks

Chapter 2Custom Blocks
â˜…

Big Idea

Custom blocks let you package repeated logic into one named command, just like a mini function.

Explanation A custom block is your own command in the My Blocks category. Instead of repeating long scripts again and again, you create one definition and call it whenever needed. This is called abstraction, and it is a core idea used by real software developers.

Why custom blocks matter

Less repetition

Write once, use many times.

Easier editing

Update inside the block and every call gets improved.

Cleaner scripts

Long chains become readable with meaningful names.

Design recipe

1

Spot repeated logic

Find a pattern you are copying at least 3 times.

2

Name your block clearly

Use action names like drawSquare, jumpStep, sayLine.

3

Add inputs if needed

Use parameters for size, speed, or words so one block can do many variations.

4

Test each call

Try at least two different input values to confirm flexibility.

Example with input

Create block: jump(height)

Define jump(height) with:
change y by height
wait 0.1 seconds
change y by -height

Reuse the same block

Call jump(20) for small jump and jump(50) for big jump. One block, many outcomes.

Pro Tip If your script scrolls too much, it is a hint that a custom block can simplify it.
Ask A.I.

Stuck? Try this prompt -

In Scratch, I made a custom block called jump(height). I want one small jump and one big jump using the same block, but both jumps look similar. Please show me how to define the block correctly with input and how to call it with two different values.

Tip: Include your custom block name and input so A.I. can return precise steps.

3.1 Building with Sound and Story

Chapter 3Sound and Storytelling
â˜…

Big Idea

A good Scratch story has three layers: visuals, words, and sound. All three need timing.

Explanation Storytelling in Scratch is about sequencing emotions. Sprites show action, dialogue explains thought, and sound sets mood. If all lines appear at once, the story feels confusing. If each element appears in order with short waits, the audience understands and enjoys the flow.

Story structure in Scratch

1

Scene setup

Choose backdrop, place sprites, set mood.

2

Dialogue and action

Use say/think blocks while sprites move or react.

3

Sound layer

Add background music and event sounds like clap, pop, or whoosh.

4

Ending

Close with a clear final message and stop all scripts cleanly.

Voice

Record your own narration to personalize stories.

Music

Loop soft music at low volume to avoid overpowering dialogue.

Silence

Short silent moments can create suspense before key events.

Example scene timeline

1

Scene starts

Backdrop: forest, Sprite A says: "I think we are lost..." for 2 seconds.

2

Add reaction sound

Play sound "whoosh", then Sprite B enters with glide and says: "Follow me!"

3

Transition cleanly

Wait 0.5 seconds, change backdrop, start calm music for next scene.

Ask A.I.

Stuck? Try this prompt -

I am making a Scratch story with 3 scenes. I have dialogue and sound effects, but the lines overlap and audio timing feels messy. Can you suggest a clean sequence using say ... for ... seconds, play sound until done, and wait so each scene feels clear?

Tip: Ask for sequence order, not just random blocks, when building story flow.

4.1 Mastering Broadcasting

Chapter 4Broadcasting
â˜…

Big Idea

Broadcasting is like directing a play: one message tells many sprites when to act.

Explanation Broadcasting is Scratch's event messaging system. One script can send a message, and multiple sprites can react to it at the same time. This helps you avoid messy timing guesses and keeps multi-sprite projects organized.

Message flow model

1

Trigger event

Player clicks start or completes an action.

2

Broadcast message

Send a named signal like scene2 or gameOver.

3

Receive and react

Other sprites run scripts with when I receive [message].

4

Chain scenes

Use one message to trigger the next, creating smooth story or game flow.

Use clear message names

Good names: intro_done, start_quiz, victory.

Avoid overlap

If too many scripts run together, add waits or stop other scripts first.

Example broadcast chain

Main controller sprite

when green flag clicked
show title for 2 seconds
broadcast [scene1]

Other sprites react

when I receive [scene1] -> hero enters
when I receive [scene1] -> music starts
Hero finishes line -> broadcast [scene2]

Naming Rule Prefer message names based on story stages (scene1_start, scene1_end, quiz_start) instead of generic names like message1, message2.
Ask A.I.

Stuck? Try this prompt -

In my Scratch project, I broadcast scene2_start but one sprite does not react. I am using when I receive [scene2_start] on that sprite. Can you give me a debugging checklist to verify message names, receiver scripts, and script timing conflicts?

Tip: For broadcast bugs, always ask A.I. for a checklist and test one item at a time.

  • Student uses at least one event + one loop
  • Student animation is visibly smooth, not random jumps

Chapter 2 - Custom Blocks (Exercise 2.3)

Expected answers

  • Repeated task examples: jump, spin, say-line, draw-shape
  • Sample inputs: sayMessage(text), jump(height), drawStar(size)
  • Debug checks: block definition updated, calls use correct inputs, sprite/script is active

Teacher check

  • Student names custom blocks meaningfully
  • At least one custom block has a useful parameter
  • Student can show reuse with different input values

Chapter 3 - Sound and Storytelling (Exercise 3.3)

Expected answers

  • Story has clear title and one-sentence summary
  • Wait blocks placed between key dialogues/scenes
  • Sound volume/timing adjusted so voice/dialogue is understandable

Teacher check

  • Beginning-middle-end is easy to follow
  • Audio supports story instead of distracting from it
  • Student can explain one post-test improvement

Chapter 4 - Broadcasting (Exercise 4.3)

Expected answers

  • Message names should be meaningful: scene1_start, quiz_start, ending
  • Troubleshooting checks: exact message name match, receiver script exists, receiver conditions allow run
  • Growth answers are reflective; no single fixed response required

Teacher check

  • Student can trace message flow from sender to receiver
  • Project avoids uncontrolled overlap of scripts
  • Final project combines all 4 chapter skills
